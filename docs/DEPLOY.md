# デプロイ手順 (Cloud Run + Google Sheets + LINEミニアプリ)

## 1. Google Sheets (運営者のみ) — JSONキー不要の方式
1. 新しいスプレッドシートを作成 (シートは起動時に自動作成される)。URLの `/d/<ID>/` が `SPREADSHEET_ID`。
2. GCP で Sheets API / Cloud Run Admin API / Cloud Build API / Artifact Registry API / Secret Manager API を有効化。
3. サービスアカウント(例 `sheets-writer`)を作成する。**キーは作らない**(組織ポリシーでキー作成が禁止されていても問題なし)。
4. このサービスアカウントに次のロールを付与 (IAM):
   - 「Secret Manager のシークレット アクセサー」(プロジェクト)
   - 「サービスアカウント トークン作成者」(**このサービスアカウント自身**に対して。サービスアカウントの権限タブ→「アクセスを許可」→プリンシパルに自分自身のメールを指定)
5. スプレッドシートを **このサービスアカウントのメールにのみ「編集者」で共有**。店舗・スタッフには共有しない (店舗は管理画面経由でのみ閲覧)。
6. デプロイ時に `--service-account sheets-writer@<プロジェクトID>.iam.gserviceaccount.com` を指定して、Cloud Run の実行アカウントにする。
(従来どおり JSON キーを使う場合は、キーを Secret Manager に保存して `GOOGLE_SERVICE_ACCOUNT_JSON` に渡す。未設定ならキーレスで動く。)

## 2. LINE
1. LINE Developers で「LINEログイン」チャネルを作成 → **チャネルID** = `LINE_LOGIN_CHANNEL_ID`。
2. LIFF アプリ (LINEミニアプリ) を作成。エンドポイントURL = `https://<Cloud RunのURL>/app`。スコープは `openid`(必須)。→ **LIFF ID** = `LIFF_ID`。
3. 各店舗の公式アカウントのリッチメニューに、管理API `POST /api/admin/registration-url` が返す URL
   (`https://liff.line.me/<LIFF_ID>?t=<店舗token>`) を設定する。token が漏れた場合は `DELETE /api/admin/registration-url/<token>` で無効化し再発行。
4. 別法人の公式アカウントとミニアプリのプロバイダーの関係は LINE の仕様に従う。導入前に、各社の公式アカウントからこのURLを開けること・userId が取得できることを実機で確認する。

## 3. Cloud Run
```
gcloud run deploy line-members --source . --region asia-northeast1 \
  --service-account sheets-writer@<プロジェクトID>.iam.gserviceaccount.com \
  --max-instances 1 --allow-unauthenticated \
  --set-env-vars LINE_LOGIN_CHANNEL_ID=...,LIFF_ID=...,SPREADSHEET_ID=...,OPERATOR_EMAIL=you@example.com,PUBLIC_ORIGIN=https://<サービスURL> \
  --set-secrets SESSION_SECRET=session-secret:latest,DATA_ENCRYPTION_KEY=data-key:latest,OPERATOR_PASSWORD=operator-password:latest
```
- `--max-instances 1` は必須 (Sheets へ全シート書き戻しのため、複数インスタンスだと上書きし合う)。
- `SESSION_SECRET` は 32 文字以上のランダム文字列。変更すると全員が再ログインになる。
- `DATA_ENCRYPTION_KEY` (32文字以上・必須級): 店舗のLINEチャネルアクセストークンと二段階認証の秘密鍵の暗号化に使う。**紛失・変更すると保存済みの値は復号できなくなる**ので、Secret Manager で厳重に保管し、`SESSION_SECRET` とは別の値にする。
- 初回起動で運営管理者が作成される。以後 `OPERATOR_PASSWORD` はシークレットから外してよい。
- 運営管理者でログイン → `POST /api/admin/tenants` で店舗作成 (登録token返却) → `POST /api/admin/admins` で店舗管理者作成。

## 4. 運用上の注意
- Sheets は書き込み1回あたり対象シートを全書き換えする。会員が数千件規模になったら DB (Firestore 等) への移行を検討 (`Store` と同じメソッドを実装すれば差し替え可能)。
- Sheets 側の手作業編集は、次回起動時に取り込まれる。稼働中のシート直接編集はしない。

## 5. 店舗ごとのLINE連携 (管理画面「LINE連携」タブ)
別法人の店舗は、**店舗の公式アカウントと同じプロバイダー内**に次を作成してもらい、値を設定する。
- LINEログインチャネル (→ チャネルID) と LIFF アプリ (→ LIFF ID、エンドポイントURL = `https://<Cloud RunのURL>/app`)
- 公式アカウントの Messaging API チャネルのチャネルアクセストークン (長期) → メッセージ配信に使用 (暗号化保存・画面には再表示されない)。Messaging API チャネルはコンソールから直接は作れない(2024-09-04〜)。LINE公式アカウントを作成し、LINE Official Account Manager で Messaging API を有効化する際に、ログインチャネルと同じプロバイダーを選ぶ(後から変更不可)。
- 会員にメッセージが届くのは、公式アカウントを友だち追加していてブロックしていない場合のみ。LIFF の「Add friend option」を有効にしておく。
- 公式LINEの「ショップカード」の配布URL (`https://lin.ee/...` 等) → 会員証の「ショップカードを開く」ボタン。LINEドメインのURLのみ設定可
- 注意: プロバイダーが異なると、ミニアプリで取得するユーザーIDと Messaging API のユーザーIDが一致せず、配信できない。
- 配信は LINE の月間メッセージ数・プランの制限に従う (店舗の公式アカウントの契約内)。

## 6. 運用メモ
- **来店QR**: 会員証のQRは署名付き・5分有効・1回限り。スタッフは管理画面「来店スキャン」(HTTPSでカメラ許可が必要) で読み取る。同じ会員の連続記録は30分抑止。
- **退会**: 会員本人(ミニアプリ)または店舗管理者が実行。データは削除せず `status=WITHDRAWN`。配信同意は取り消され、検索は既定で除外。再登録で同じ会員番号に復帰。
- **パスワード再設定**: 管理画面の管理者一覧(店舗管理者=自店舗スタッフ / 運営=全員)から「再設定リンク」を発行して本人に渡す (1時間・1回限り)。二段階認証の解除も同じ画面。
- **二段階認証**: 各管理者が「アカウント」タブで任意に有効化 (認証アプリ + 回復コード8個)。
- **Sheets の列追加**: 新バージョンで列が増えても、起動時に既存データを保持したまま自動で列が追加される。

## 7. 二段階認証 (アプリ不要のパスキー)
- 管理画面「アカウント」→「パスキー」で、端末の指紋認証・顔認証・画面ロック解除をログインの二段階目として登録できる (認証アプリは不要)。認証アプリ(6桁コード)とも併用でき、どちらでもログインできる。
- パスキーは「ドメイン」に紐づく。**管理画面は常に同じURLで開く**こと。Cloud Run は URL を2種類発行する (`…-<プロジェクト番号>.<リージョン>.run.app` と `…-xxxx-an.a.run.app`)。環境変数 `PUBLIC_ORIGIN` に、普段使うURL(例 `https://line-members-730765585909.asia-northeast1.run.app`)を設定して固定すると、取り違えを防げる。独自ドメインへ移行するとパスキーは作り直しになる。
- 端末を紛失したときは、店舗管理者(自店舗スタッフ)または運営が「2FAリセット」で、パスキーと認証アプリの設定をまとめて解除できる。

## 8. 会員証デザイン (管理画面「会員証デザイン」タブ)
- 店舗管理者が、カード面(背景=単色/グラデーション/画像、文字色、書体、角の丸み、ロゴ、店舗名・タイトル、表示する項目、QRの位置)と、会員画面の見た目(ボタンの色、背景色、メッセージ、一覧/ショップカードボタンの表示)を設定できる。プレビューを見ながら調整し、「保存」で会員のスマホに反映される。
- 会員は「カード画像を保存」で、カードをPNG画像として保存できる (QRは5分で失効するため、保存画像には含めない)。管理画面からも「カード画像をダウンロード」できる。
- 画像(ロゴ/背景)は端末側で縮小・圧縮してアップロードされ、**スプレッドシート(`card_assets` シート)に4万文字ずつ分割して保存**される。1画像400KBまで・1店舗12枚まで。使っていない画像は、保存時に(1時間以上たったものが)自動削除される。SVGは許可しない。
- 店舗数や画像が増えてスプレッドシートが重くなったら、画像だけ Cloud Storage 等へ移す (`src/card.js` の `CardService` の画像まわりを差し替える)。
- 店舗間の分離: 画像は店舗ごとにしか取得できず、他店舗の画像IDをデザインに指定すると保存時に拒否される。

## 9. 会員一覧 / 配信の同意 / カードの店舗名
- **会員一覧**: 20件ずつのページ送り(50・100件も選べる)。「表示項目を設定」で、標準項目(会員番号・状態・登録日・来店回数・最終来店)と、会員登録フォームの全項目から、表示する項目と並び順を選べる。列の見出しをクリックすると並び替え。表示項目と件数の設定は、**そのブラウザに保存**される(端末ごと)。
- **配信への同意**: 管理画面「会員登録フォーム」の上部の「配信への同意(チェックボックス)」で、LINE配信・メール配信・キャンペーン案内の同意チェックボックスを、ワンクリックで表示/非表示にできる。文言は「文言を編集」で変更。同意は**必須にできない**(任意)。チェックを入れた会員だけが配信対象になる。会員は、会員証の画面の「LINEでのお知らせ」から、あとでオン/オフできる(既存の会員もここから同意できる)。
- **カードの店舗名**: 「会員証デザイン」→「文言」の「カードに表示する店舗名」(空欄なら登録されている店舗名)。会員画面の見出しも同じ名前になる。プレビューのカードの店舗名/タイトルをクリックすると、入力欄に移動する。

## 10. 会員画面: 情報を隠す / お知らせの設定
- 会員証の画面の「情報とQRコードを隠す」ボタンで、氏名・来店情報・登録情報の一覧・QRコードをまとめて隠せる(会員番号は下3桁だけ表示)。隠している間は、QRコードを取得もしない。「表示する」で元に戻る。「カード画像を保存」も、隠した状態のときは隠した画像になる。
- 会員証の画面の「LINEでのお知らせ」で、会員本人が、LINEでの配信の受け取りをオン/オフできる(登録フォームに同意のチェックボックスがなくても使える)。登録フォームに同意項目がある場合は、その値も同じ状態にそろう。この欄は、管理画面「会員証デザイン」の「会員画面の見た目」で、表示/非表示を選べる(既定は表示)。

## 11. クーポン配信 / 友だち追加の必須化
### クーポン (管理画面「クーポン」タブ)
- 店舗管理者がクーポンを作成 (クーポン名・特典・利用条件・利用開始日・有効期限)。日付は日本時間で、その日の終わりまで有効。
- 「メッセージ配信」で、メッセージにクーポンを添付して送る(クーポンだけの配信も可)。LINEには、クーポンのカード(特典・期限・「クーポンを使う」ボタン)が届く。有効期限切れ・終了済みのクーポンは添付できない。
- **クーポンが配布されるのは、メッセージが実際に届いた会員だけ**(送信に失敗したまとまりの会員には配布しない)。同じ会員に重複して配布しない。
- 会員は、LINEのカードのボタン、または会員証画面の「使えるクーポン」から開き、「クーポンを使う」でQR(5分有効)を表示。スタッフが「来店スキャン」(または管理画面の会員番号入力)で読み取ると**使用済み**になり、会員の画面も自動で切り替わる。**1人1回**。退会した会員・他店舗・期限切れ・使用済みは使えない。
- クーポンのリンクは、店舗の LIFF ID と登録URLのtokenから作られる。事前に「LINE連携」タブで LIFF ID を設定しておくこと。

### 友だち追加を会員登録の条件にする (管理画面「LINE連携」)
- 会員登録の前に、**サーバーがLINEのAPI(`GET /v2/bot/profile/{userId}`)に問い合わせ**、その公式アカウントの友だち(ブロックしていない)かを確認する。友だちでなければ、案内画面(「友だち追加する」ボタン)を出し、登録できない。端末側の申告は使わない。退会後の再登録でも確認する。
- **既定**: メッセージ用チャネルアクセストークンが登録されている店舗では、自動的に「必須」。「必須にしない」にも変更できる。トークンが無い間は確認できないため、確認しない。
- 友だち追加ボタンの移動先は、公式アカウントのベーシックIDから自動で作る。「友だち追加のURL」(`https://lin.ee/…`)を設定すれば、そちらを優先。
- **重要(同じプロバイダー)**: 会員のユーザーID(LINEログインチャネル)と公式アカウント(Messaging API)が同じプロバイダーでないと、友だちでも「友だちではない」と判定され、誰も登録できなくなる。店舗ごとに、同じプロバイダーでLINEログインチャネルと公式アカウントを用意すること。
- LINE側の障害・トークン不正で確認できないときは、安全側に倒して登録させず、案内を表示する。
- LIFF の「Add friend option」(On)も併用すると、ミニアプリを開くときに友だち追加を促せる。
- **既存の店舗への影響**: すでにトークンを登録済みの店舗は、次のデプロイから、既定で「必須」になる。同じプロバイダーでない店舗は、先に「必須にしない」へ変更してから反映すること。

## 12. 会員登録フォームの編集 (下書き → 保存)
- 「会員登録フォーム」タブでの変更(項目の追加・編集・必須・表示/非表示・並び替え・テンプレート・同意チェックボックス)は、**まず下書きにだけ反映**され、画面上部の **「保存」を押すまで、会員の登録画面には反映されない**。プレビューも、保存前の内容を表示する。
- 保存は**1回の操作でまとめて反映**され、変更履歴(バージョン)も1つだけ増える。途中で1つでも失敗(禁止語・HTML・選択肢の不足など)すると、**全部取り消され**、下書きはそのまま残るので、直して再度保存できる。
- 「変更を破棄」で、未保存の変更をすべて捨てられる。未保存のまま、別のタブ・店舗の切り替え・ログアウト・ブラウザを閉じる操作をすると、確認が出る。
- 他の管理者が先に保存していた場合は、上書きせずに、その旨を表示する(「変更を破棄」で最新を読み込み直す)。
- 保存の操作は、監査ログに `FORM_BATCH_SAVE` として記録される。

## 13. 誕生日メッセージ・クーポン

管理画面「誕生日配信」タブ。誕生日の N 日前(0=当日)から、有効な会員でLINE配信に同意した会員へ、**1年に1回だけ**メッセージ(とクーポン)を送る。会員登録フォームに「生年月日」項目(マスターから追加)が必要。

- 手動で送りたい場合: 「会員」「メッセージ配信」の絞り込みに「誕生日までの日数」(以下)が使える。
- クーポンの「付与からの有効日数」(例: 30)で、誕生日クーポンの使える期間を限定できる。前回分が使用済み/期限切れなら、翌年また付与される。
- 1回の実行で送るのは最大200人(超過分は翌日に持ち越し)。送信に失敗した会員は「送信済み」にならず、翌日再試行される。
- 自動実行には Cloud Scheduler が必要 (無くても「今すぐ実行」で手動送信はできる)。

### 自動実行の設定 (1回だけ)
```bash
# 1) 合言葉を作って Secret Manager に保存
openssl rand -hex 24 | tr -d '\n' | gcloud secrets create cron-secret --data-file=-
gcloud secrets add-iam-policy-binding cron-secret \
  --member="serviceAccount:$(gcloud projects describe $(gcloud config get-value project) --format='value(projectNumber)')-compute@developer.gserviceaccount.com" \
  --role=roles/secretmanager.secretAccessor
# 2) Cloud Run に渡して再デプロイ (§3 のデプロイコマンドの --set-secrets に ,CRON_SECRET=cron-secret:latest を追加)
# 3) 10分おきに呼び出す (誕生日配信は日本時間の朝9時以降に1日1回、予約メッセージは指定時刻に送られる)
gcloud services enable cloudscheduler.googleapis.com
gcloud scheduler jobs create http birthday-daily --location=asia-northeast1 \
  --schedule="*/10 * * * *" --time-zone="Asia/Tokyo" --http-method=POST \
  --uri="https://<サービスURL>/api/cron/run" \
  --headers="Authorization=Bearer $(gcloud secrets versions access latest --secret=cron-secret)"
```
`CRON_SECRET` が未設定のときは、このエンドポイントは常に 401 を返す。

## 14. 会員画面のコンパクト化 / お知らせの内容別設定
- 会員証の下に「隠す / 画像保存 / お知らせ / メニュー」を1行で配置。登録情報は折りたたみ、変更・退会は「メニュー」に集約。
- 「お知らせ」: LINE全体のオン/オフに加え、「お知らせ・キャンペーン」「クーポン」「お誕生日のお祝い」を個別に選べる。クーポン付き配信はクーポンを断った会員に、誕生日配信は誕生日を断った会員に送られない。
- 氏名がカードに出ない場合に備え、氏名の列が空でも「氏名/名前」を含む名前の項目の値を使う。

## 15. 来店回数でメッセージ・クーポン (管理画面「来店回数配信」)
- 「5回目の来店」「5回ごと」などのルールを予約。来店が記録された直後(QR読み取り・手動記録)に、条件を満たした会員へ自動送信 (クーポン添付・有効日数・開始/終了日の指定可)。
- 同じ会員・同じ来店回数には1回だけ。LINE配信に同意していない/該当の内容を断っている会員には送らない。送信に失敗した場合は記録のみで再送しない(一覧に失敗数が出る)。
- メッセージの `{名前}` `{回数}` は会員の名前・来店回数に置き換わる。

## 16. 予約メッセージ(定期) / 会員ランク / 店舗ごとの機能制限
- **予約メッセージ(定期)**: 「予約メッセージ」タブ。1回だけ/毎日/毎週/毎月と送信時刻(日本時間)、配信先の絞り込み、クーポン添付を設定。時刻になると自動送信(同じ日に二重送信しない)。自動実行には §13 の Cloud Scheduler(`/api/cron/run` を10分おき)が必要。
- **会員ランク**: 「会員ランク」タブ。来店回数ごとに称号・★の色・カードの色を設定(最大10ランク、ランクが上がるごとに★が1つ増える)。会員証の右上に「★★ 称号」が出て、カード色を設定したランクは背景(画像以外)がその色になる。会員画面には「次のランクまであと○回」も出る。
- **店舗ごとの機能制限**: 運営 → 「店舗」の「機能設定」。会員証デザイン/来店スキャン/メッセージ配信/予約メッセージ/誕生日配信/来店回数配信/クーポン/会員ランク を店舗ごとにオフにできる。オフにした機能は、その店舗の管理者・スタッフに表示されず、APIも403になる(運営は常に使える)。自動配信もその店舗では止まる。

## 17. 会員証デザインのプレビュー / 「キャンペーン情報」の表示
- 「会員証デザイン」のプレビューは、会員が実際に見る画面(`/app?preview=1`)をそのまま埋め込んでいる(サンプルデータ・通信なし)。設定した見た目とボタン構成は、実機と必ず一致する。
- 登録情報の「LINEでお知らせ…」「キャンペーン情報…」のような同意項目は、未登録ではなく、実際の受け取り設定を はい/いいえ で表示する。「キャンペーン情報」は会員画面の「お知らせ」の「お知らせ・キャンペーン」と同じ設定(どちらを変えても連動)。

## 18. ランクで絞り込んだ配信
会員ランクを有効にすると、「会員」の検索・「メッセージ配信」・「予約メッセージ」の絞り込み条件に「会員ランク」(称号を選択)が使える。例: 「会員ランク = ゴールド」で、毎月1日にクーポン付きの予約メッセージ、など。

## 19. 会員ランクの追加設定
- 会員証の下の「最終来店…」の行は、カードの中に最終来店・来店回数が出ているときは表示しない(どちらもカードに出していないときだけ表示)。
- 「会員画面に『次のランクまであと○回』を表示する」をオン/オフできる(会員ランクタブ)。
- ランクごとの「最終来店から○日で1つ下がる」: その日数を超えて来店がないと、1つ下のランクになる(下のランクの日数も超えていれば、さらに下がる)。来店するとすぐに元に戻る。空欄ならランクダウンしない。ランクダウン中は会員画面に「ご来店で○○に戻ります」と出る。
- 会員ランクタブの下に、ランクごとの会員証のプレビューを表示。

## 20. 管理画面のスマホ・タブレット表示
- 画面幅900px以下では、タブをハンバーガーメニュー(左上のボタン)にまとめ、横スクロールなしで切り替えられる(PCの表示は従来どおり)。

## 21. 管理画面のログイン状態の保持
- ログイン画面の「このブラウザでログイン状態を保持する(30日)」(初期はオン)を選ぶと、タブやブラウザを閉じても、30日間ログインしたままになる。使うたびに期限が延びるので、30日以上使わなかったときだけログインし直しになる。
- チェックを外すと、従来どおり(タブを閉じるまで・最長8時間)。共用のパソコンでは外すこと。
- パスワード変更・2段階認証のリセット・アカウントの無効化をすると、保持中のログインも他の端末で無効になる。

## 22. 追加機能(クーポン・パスワード・来店方式・カード・読み仮名・使い方ガイド)
- **何度でも使えるクーポン**: クーポン作成で「期間中は何度でも使える」をオン(「1日1回まで」も選べる)。使用後も使用済みにならず、有効期限まで繰り返し使える。
- **仮パスワード / パスワード設定**: 管理者一覧(運営=全員、店舗管理者=自店舗のスタッフ)の「仮パスワード」(ランダムに発行して1回だけ表示)、「パスワード設定」(指定の文字列)。どちらも、本人は最初のログインで自分のパスワードに変更するまで他の操作ができず、その人の既存のログインは無効になる。自分のパスワード変更は「アカウント」タブ。
- **来店の記録方式(店舗ごと)**: 「来店スキャン」タブの上部で選択。(1)会員のQRを店舗が読み取る(従来) (2)店舗のQRを会員が読み取る: 管理画面に60秒ごとに切り替わるQRを表示し、会員がスマホのカメラ(またはLINE)で読み取ると、ミニアプリが開いて来店が記録される(30分以内の重複は記録しない)。(2)の店舗では、会員証にQRは出ず、「店頭のQRを読み取って来店を記録」ボタンが出る。LIFFの設定(LINE Developers)で「Scan QR」を有効にすると、アプリ内の読み取りも使える。
- **会員証のメタリックと帯**: 「会員証デザイン」で、テンプレートにゴールド/シルバー/ブロンズ/プラチナ/ローズゴールド/ブラッククローム、背景の種類に「メタリック」。「帯(横ライン)」で上・中・下の帯の表示・色・太さ。会員ランクごとのメタリックも設定可。
- **読み仮名**: 標準項目に「氏名(読み仮名)」「姓(読み仮名)」「名(読み仮名)」を追加。項目の編集で「入力できる文字」(ひらがな/カタカナ/アルファベット)を指定でき、ひらがな↔カタカナは自動変換、全角英字は半角にそろえる。
- **使い方ガイド**: 管理画面の各ページ右上の「？ 使い方」ボタンで、その画面の説明(何をする画面か・手順・ポイント)をポップアップ表示。

## 23. 氏名の読み仮名の表示 / カードの裏面にQR
- 「会員証デザイン」→「カードに表示する項目」の「氏名の読み仮名」をオンにすると、氏名の上に読み仮名が小さく出る。読み仮名は、登録フォームの「氏名(読み仮名)」、または「姓(読み仮名)」「名(読み仮名)」の項目の値。姓・名が別項目のときは、「氏名の並び順」の設定に従って並べ替える。
- **カードの裏面にQR**: 「QRコードの位置」に「カードの裏面(スワイプで表示)」を追加。会員がカードを左右にスワイプ(またはタップ)すると、カードが裏返ってQRが出る(従来の「カードの下」「カードの中」も選べる)。
- この機能は、運営が店舗ごとにオン/オフ: 運営 → 店舗の「機能設定」→「カードの裏面にQR(スワイプで表示)」。オフの店舗では、選択肢が出ず、すでに設定していても会員画面には「カードの下」で表示される(オンに戻せば、設定どおりに戻る)。
- **裏面QRの位置調整**: 「QRコードの位置」を「カードの裏面」にすると、横の位置・縦の位置(中央から±40%)、QRの大きさ(小・中・大)、裏面のタイトル・会員番号の表示を調整できる。プレビューは「プレビューを裏面にする」で裏面になる(調整中は自動で裏面)。QRはカードの端からはみ出さない。

## 24. 配信予定(まとめの画面)
管理画面の「配信予定」タブ。誕生日配信(オン/オフ・何日前から・今日の送信予定の人数・前回の結果)、予約メッセージ(次の配信日時の近い順・「実行待ち」の表示)、来店回数配信(有効なルールと送信数)、自動配信の稼働状況(10分おきの自動実行が動いているか。30分以上確認できないと赤い警告)をまとめて表示する。各カードの「設定を開く」で、それぞれの設定画面へ移動できる。
